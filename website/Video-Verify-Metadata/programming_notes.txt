### Docker AWS Upload:

1) Install AWS CLI: Ensure you have the AWS CLI installed and configured with your credentials.

2) Create an ECR Repository: Create a repository in ECR to store your Docker image.

3) Authenticate Docker to ECR: Use the AWS CLI to authenticate Docker to your ECR registry.

4) Tag Your Docker Image: Tag your Docker image to match the ECR repository URI.

5) Push the Docker Image: Push the tagged image to your ECR repository.


### Detailed Steps:
### Replace your-region with your AWS region (e.g., us-west-2) and your-account-id (e.g. 412343402708) with your AWS account ID.

1. Install AWS CLI
If you haven't installed the AWS CLI, you can download and install it.

2. Create an ECR Repository
aws ecr create-repository --repository-name video-verify-metadata --region us-west-2

3. Authenticate Docker to ECR
aws ecr get-login-password --region us-west-2 | docker login --username AWS --password-stdin 412343402708.dkr.ecr.us-west-2.amazonaws.com

4. Tag Your Docker Image
docker tag video-verify-metadata:latest 412343402708.dkr.ecr.us-west-2.amazonaws.com/video-verify-metadata:latest

5. Push the Docker Image
docker push 412343402708.dkr.ecr.us-west-2.amazonaws.com/video-verify-metadata:latest

Notes
Ensure your AWS CLI is configured with the necessary permissions to create repositories and push images.
Replace placeholders with your actual AWS account details and region.
This will upload your Docker image to AWS ECR, making it available for deployment on AWS services like ECS or EKS.

### ECS Setup

1) Create cluster

aws ecs create-cluster --cluster-name vv-metadata-initial-test

2) Create and Attach an Execution Role
    a) Create an IAM Role for ECS Tasks:

    Go to the IAM console.
    Click on "Roles" in the left navigation pane.
    Click on the "Create role" button.
    Select "ECS" as the service that will use this role.
    Choose "ECS Task" as the use case.
    Click "Next: Permissions".
    Attach the AmazonECSTaskExecutionRolePolicy policy.
    Click "Next: Tags" (optional) and then "Next: Review".
    Give the role a name, e.g., ecsTaskExecutionRole.
    Click "Create role".

    b) Update Your Task Definition:

    Add the executionRoleArn field to your task definition JSON.
          "executionRoleArn": "arn:aws:iam::123456789012:role/ecsTaskExecutionRole",

3) Create a Task Definition

The task definition is located at infra/ecs/task-definition.json

4) Register the task definition:

aws ecs register-task-definition --cli-input-json file://infra/ecs/task-definition.json

5) Run the task (services can be updated but you kill and restart tasks)

Setting up ltlprotect.com:

To add CloudFront to your setup and use the domain name http://ltlprotect.com/, follow these steps:

Step-by-Step Guide
Register the Domain with Amazon Route 53:

Register the domain ltlprotect.com using Amazon Route 53.
Create a hosted zone for ltlprotect.com.
Set Up Your Flask Application on EC2:

Yes, it is generally a good practice to disable the public IP for your ECS Fargate tasks when using CloudFront. This enhances security by ensuring that your application is only accessible through CloudFront, which can provide additional security features such as DDoS protection and WAF (Web Application Firewall).

Steps to Disable Public IP and Set Up CloudFront
Update ECS Task Definition:

Modify your ECS task definition to disable the public IP.
Create an Application Load Balancer (ALB):

Use an ALB to route traffic from CloudFront to your ECS tasks.
Create a CloudFront Distribution:

Set up CloudFront to use the ALB as the origin.
Update Route 53 DNS Records:

Point your domain to the CloudFront distribution.
Detailed Steps
1. Update ECS Task Definition
Modify your ECS task definition to disable the public IP:

2. Create an Application Load Balancer (ALB)
Create an ALB:

Go to the EC2 console.
Under "Load Balancing", choose "Load Balancers" and click "Create Load Balancer".
Choose "Application Load Balancer" and follow the prompts to create it.
Configure the ALB:

Set the ALB to listen on port 80 (HTTP) or 443 (HTTPS).
Add your ECS tasks as targets in a target group.
3. Create a CloudFront Distribution
Go to the CloudFront Console:

Open the Amazon CloudFront console.
Create a New Distribution:

Click "Create Distribution".
Choose "Web" as the delivery method.
Configure the Origin Settings:

Set the "Origin Domain Name" to the DNS name of your ALB.
Ensure the "Origin Protocol Policy" is set to "HTTP Only" or "HTTPS Only" based on your ALB configuration.
Configure the Default Cache Behavior Settings:

Set the "Viewer Protocol Policy" to "Redirect HTTP to HTTPS" or "HTTP and HTTPS" based on your requirements.
Configure other settings as needed.
Configure the Distribution Settings:

Set the "Alternate Domain Names (CNAMEs)" to ltlprotect.com.
If you have an SSL certificate for your domain, configure it under "SSL Certificate".
Create the Distribution:

Click "Create Distribution" and wait for it to deploy.
4. Update Route 53 DNS Records
Go to the Route 53 Console:

Open the Amazon Route 53 console.
Select the Hosted Zone for ltlprotect.com:

Go to "Hosted Zones" and select ltlprotect.com.
Create an A Record:

Create an A record that points to the CloudFront distribution.
Use an alias record to point to the CloudFront distribution.
Summary
By following these steps, you can disable the public IP for your ECS Fargate tasks and set up CloudFront to serve your Flask application using the domain http://ltlprotect.com/. This setup includes creating an ALB to route traffic to your ECS tasks, configuring CloudFront to use the ALB as the origin, and updating your Route 53 DNS records to point to the CloudFront distribution.
